It's the real CLI

Not a reimplementation. Each agent is claude itself, the same TUI you run on a laptop, in a tmux session on the server. From any shell on the box, cc my-project/slot-3 joins that very session.

One session, every device

The process lives on the server, so a laptop and a phone are two windows onto the same run, mid-task, with no handoff step. Lock the screen and the work carries on. Your phone buzzes when it finishes.

Your code stays put

One machine, one persistent volume, one GitHub token, in an account that is yours if you self-host, and one customer's alone if we run it. English dictation transcribes on the box itself.

Every agent, one screen

The app opens on the Mux: every project down the side, each with its worktree slots and a light on every one (working, finished while you were looking elsewhere, waiting for you). In the middle, up to eight panes side by side, each a Claude, a shell, or a command line of your own, in a terminal that lives on the server.

A worktree per agent

Every project gets its own checkouts, one per slot (ten by default), so agents never edit the same files. A new one starts from the latest main, unless the slot holds work, which is never touched. /exit resets a slot for the next task.

Workspaces for parallel tasks

A second full clone of the repository on a branch of its own, with slots of its own: one task on main, "Feature A" on feat/a beside it. Up to five per repository by default, nested under the project.

Terminals that behave

Scroll with the wheel, copy to your real clipboard, click links, attach any file with 📎, and pick your font. A plain shell opens beside any slot's Claude, and Hebrew and Arabic read the right way round.

Two screens, two windows

Open the Mux in a second window and each shows its own page of panes, 1–3 on one screen and 4–6 on the other. Swap any pane with any other, even across windows.

A phone with the keys

One pane at a time, with two rows of keys a phone keyboard lacks: Esc, arrows, Shift-Tab, the numbered choices, and Ctrl and Alt for any chord. Plus a line of plain text that takes the phone's own dictation.

Close the laptop

Nothing in the browser owns the work. Shut the lid mid-task and it finishes. Open your phone and every agent is there, in the slot you left it. Closing a pane stops nothing.

Ten slots, eight panes and five workspaces are defaults, not limits. Each deployment sets its own, up to 32, 16 and 20, in its config or from its box page, and lowering one hides what is above it without deleting anything.

Everything else is on the box too

The same machine the agents run on, reached from the same page, behind the same login.

A real Chrome

The Browser pane is Google Chrome running on the box, streamed to you as video. Its tabs and profile are the box's, so you sign in once and a Claude there drives the same window over DevTools while you watch, from a laptop or a phone.

VS Code, for files and diffs

The full editor with the official Claude Code extension, laid out to fit a phone. Its Claude panel follows you between devices: a second device joins the same live run rather than starting another.

Hear it, and talk it over

🔊 on any pane reads Claude's last message aloud, at any speed, with Hebrew voices too. Talk it over starts a spoken conversation about that message with a model that has no tools and cannot act.

A buzz when it's done

When an agent you aren't watching finishes, or is waiting on you, your phone says which and what it said. A tap opens that slot, joined to the session already running there.

A page for the box itself

Every session and service on the machine, what each holds, what is wrong in plain words, and every setting of the deployment, editable in place with a check that the login still holds after you apply it.

Keeps itself current

The Claude Code CLI updates daily. TripleC itself can follow this repository when you choose: only commits that have soaked, only when no agent is busy, tested first, and rolled back if anything fails.

Two ways to run it

Same code, same MIT licence, same repository. The difference is whose account the machine boots in, and who gets paged when it doesn't.

Self-hosted

Freeand not a trial

  • You pay AWS, not us — roughly $75/month for the instance and load balancer left running, plus model usage.

How it works

One EC2 instance behind a load balancer, with a persistent volume that survives instance replacement. No Kubernetes, no control plane, nothing to operate. Managed is this same diagram in our account instead of yours, not a different product. Already have a Linux VM? Host mode installs the same thing onto it, with no AWS at all.

Installs like an app

Add to Home Screen on iOS, or the install icon on Android and desktop. The icon opens the Mux. A project can have an icon and a window of its own, for the editor on that project.

Survives bad networks

The server keeps every session alive when a phone locks or the signal drops. Reattaching picks up the same session mid-task, including work started on another device.

Read this part

This is a web page that runs shell commands on a machine. That's the product, not a side effect. Anyone who logs in has a shell. Deploy it as one person's workspace, not a shared service, and not something you hand a password to a stranger for.

Which is why authentication is enforced inside the process that runs the terminals, and never delegated to nginx or the load balancer alone. That design comes from getting it wrong: an earlier version of this project shipped with its API reachable without credentials, because a proxy config described a gate that had never been written and every document repeated the claim.

Closed by default

  • The server refuses to start without a strong password and cookie key.
  • Routes are gated by an allowlist, so a new endpoint is private unless deliberately opened.
  • Every WebSocket, the terminals and the browser included, needs the same login.
  • Rotating the password invalidates every existing session.
  • Login throttling at the proxy and in the app.
  • Least-privilege IAM by default; account-wide access is opt-in and documented.

Checked by machine, not by comment

  • A test suite boots the real server and asserts that every route and every socket refuse an unauthenticated caller.
  • The deploy script runs it first and refuses to deploy on failure.
  • After deploying, it curls the live URL and aborts if the API answers without a login. A self-update makes the same check, and rolls back if it fails.

The last time this was checked only by a comment, the comment was wrong for months.

Full threat model, what it does and doesn't defend against, and how to cut the blast radius: docs/SECURITY.md. What a managed instance means for the same questions: docs/MANAGED.md.

Self-host it

You need an AWS account, a Route53 hosted zone you control, and Bedrock model access enabled. About 20 minutes, most of it waiting for first boot. 

1 · point it at your domain
cp triplec.config.example.json triplec.config.json
$EDITOR triplec.config.json        # domainName + hostedZoneName

2 · go
./deploy.sh

It validates your config, runs the tests, deploys the stack, waits for the instance, ships the app, then verifies that the live URL requires a login. Re-running it is safe and keeps your projects and history.

Get it on GitHub Read the deploy guide

Already have a Linux VM? Host mode installs TripleC onto an existing Ubuntu 24.04 machine as its developer: no AWS, your own claude /login, your repositories where they already are, reached through the VM's own HTTPS proxy or a tailnet. docs/HOST.md.

Bringing existing work across? ./migrate.sh clones your repos onto the volume and copies your local Claude Code history up, rewriting the paths so past conversations stay resumable.

What it isn't

Multi-user

One login (a password, or an allowlist through Google or any OIDC provider), no per-user permissions, no audit of who did what. It's one person's workspace, and a managed instance is one customer's.

Free of infrastructure

Self-hosted, it's about $75/month of AWS left running, plus model usage. Managed, that bill is ours for now, which is exactly why "free" has a "for now" attached.

Sandboxed

Claude runs with real permissions by default. Prompt injection reaching a shell is a genuine risk with no clean fix.
